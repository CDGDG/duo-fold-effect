# 대체 힌지 센서 조사 — 2026-09-11

## 결론

기존 조사 대화의 관련 답변을 끝까지 읽고 원문과 코드를 대조했다. 양쪽 IMU로 연속 힌지 각도를 계산하는 기술은 실제 존재한다. 그러나 이 기기에서 일반 앱에 허용된 양쪽 IMU 입력을 확보한 것은 아니다. 공개 센서만으로 모든 자세에서 연속 각도를 얻는 Galaxy Fold 구현은 이번 조사에서 확인하지 못했다.

참조 대화가 영상 제작자의 구현을 보조 IMU 방식으로 의심한 것은 증거가 없는 가설이다. 내부 화면 조기 점등도 영상 조작의 증거가 아니다. 우리 실험에서도 ADB 도우미를 통해 조기 점등이 가능했다. Presentation과 AGSL 사용 설명만으로 센서 종류나 디스플레이 전원 제어 방법까지 확인되는 것은 아니다.

## 1. 양쪽 IMU: 실제 알고리즘은 존재

[ST 기술 설명](https://blog.st.com/lid-angle-detection/)은 각 패널의 LSM6DSV16X 가속도·자이로를 융합해 상대 힌지 각도를 계산한다. 가속도만으로는 동적 움직임과 중력을 분리하기 어렵고 힌지가 중력과 평행한 자세에 약점이 있어 자이로를 함께 사용한다. 라이브러리는 ST 담당자 문의 방식이다. 이것이 삼성 앱용 SDK나 권한 우회 수단이라는 뜻은 아니다.

기기의 lsm6dsv_0 / lsm6dsv_1 이름은 관련성을 검토할 단서이나, ST 예제와 정확히 같은 부품·알고리즘을 사용한다는 증거는 아니다. 보조 센서 SSENSOR 제한은 별도로 해결해야 한다. 기존 확인 결과 SSENSOR는 signature|privileged이며 일반 pm grant 대상이 아니고, 비루팅 Shizuku의 shell UID도 기존 shell 등록 실패를 해결하지 못한다.

물리적 한계에 대한 추론: 센서가 있는 절반을 고정하고 반대 절반만 움직이면 공개 IMU 값은 거의 같아도 힌지 각도는 바뀐다. 따라서 한쪽 IMU만으로 임의 자세의 상대 각도를 유일하게 복원할 수 없다. 반대 절반을 고정한 시연에서는 자이로 적분으로 근사할 수 있지만, 휴대폰 전체를 돌리는 동작 및 드리프트와 구별해야 한다. 같은 IMU에서 만들어진 gravity/rotation vector를 여러 개 읽는 것만으로 반대쪽 측정이 생기지 않는다.

## 2. KAMI 오픈소스: 각도 측정 사례로 오인하면 안 됨

[KAMI 저장소](https://github.com/maxwase/kami)의 다음 파일을 실제 읽고 로컬에 조사용 사본을 저장했다.

- [motion.ts](https://github.com/maxwase/kami/blob/master/src/device/motion.ts): DeviceMotion 가속도와 평활화.
- [posture.ts](https://github.com/maxwase/kami/blob/master/src/device/posture.ts): Flat/Creased/Closed 상태.
- [main.ts](https://github.com/maxwase/kami/blob/master/src/main.ts): 가속도로 안정성·방향을 판단하고 접힘 상태 변경으로 애니메이션 시작.

코드상 `foldedNow && !deviceFolded`에서 fold animation을 만들며, 연속 물리 힌지 각도를 복원해 매 프레임 입력하는 구조가 아니다. 공개 센서를 사용한 접기 상호작용 사례는 맞지만 현재 문제의 해결 증거는 아니다. 로컬 사본은 `artifacts/kami-*.ts`에 있다.

## 4. 공개 자기장 센서: 아직 시험할 가치가 있는 가설

닫힘용 자석과 패널 상대 위치가 공개 자기장 센서에 재현 가능한 변화를 만든다면 보정 곡선으로 각도를 근사할 가능성을 시험할 수 있다. 이번 검색에서 이를 Galaxy Fold의 전 구간 연속 각도로 구현한 검증 가능한 앱·소스는 찾지 못했다. 각도에 따른 변화가 충분한지, 동일한 값이 여러 각도에서 발생하는지부터 미확인이다. 주변 자기장·금속·케이스·전체 자세 변화에 민감할 수 있다.

다음 연결에서 애니메이션 수정 전에 할 실험:

1. 자기장 2·비보정 자기장 14·자이로 4·힌지 36을 함께 기록하고 센서별 등록 결과와 실제 이벤트를 보존한다.
2. 케이스와 주변 금속 조건을 기록하고, 알려진 여러 각도에서 정지 및 왕복 접기를 반복한다.
3. **힌지 각도는 고정한 채 기기 전체를 회전**하는 대조 시험을 반드시 한다. 접힘과 전체 움직임을 구별하지 못하면 일반 사용용 각도 입력으로 채택하지 않는다.
4. 곡선 재현성·개폐 방향 차이·정지 중 흔들림·자세 변경 오차를 먼저 평가한다. 신호가 각도별로 구별되지 않으면 모델 복잡도를 올려 성공처럼 포장하지 않는다.
5. 한쪽을 고정한 자이로 추정은 별도의 제약된 시연으로 평가한다. 일반 사용 성공이라고 보고하지 않는다.

원래 Reddit 영상 제작자의 실제 센서 타입·권한·raw 로그·구현 저장소는 아직 확보하지 못했다. 추정 방식이나 영상 진위를 단정하지 않는다.
